# i18n Reference

How the Takt i18n system works — the schema, conventions, and extension points.

## Overview

Takt ships with English (`en`) and Swedish (`sv`). The implementation is a thin custom layer with no external library: a single `strings.ts` file, a React context, and a `detectLanguage` helper.

## `strings.ts` schema

Every user-facing string is a key in the `strings` object. Each key maps to an object with an `en` and `sv` value:

```typescript
'key.name': { en: 'English copy', sv: 'Swedish copy' },
```

The object is declared `as const satisfies Record<string, Translation>`, which gives two guarantees at compile time:

1. **Key parity** — every key must have both `en` and `sv`. A missing language is a type error, not a runtime gap.
2. **Literal types** — string values retain their exact type (not widened to `string`), so autocomplete shows the actual copy.

**Adding a new string:** add the key with both values in the correct section. TypeScript will error if one language is missing.

**Adding a new language:** add the locale to `Lang` in `strings.ts` and `Translation`, then add the new property to every entry. TypeScript will flag every missing translation.

## Key naming convention

Keys are dot-separated, following a `<screen>.<concept>` pattern:

| Prefix         | Scope                                                     |
| -------------- | --------------------------------------------------------- |
| `nav.`         | Global navigation labels                                  |
| `home.`        | Home screen                                               |
| `configure.`   | Configure screen                                          |
| `run.`         | Run screen                                                |
| `complete.`    | Complete screen                                           |
| `account.`     | Account screen                                            |
| `voice.`       | Voice overlay (progress, errors, rate-limit copy)         |
| `mic.`         | Mic button                                                |
| `passkey.`     | Passkey prompt sheet                                      |
| `presets.`     | Presets drawer                                            |
| `savePreset.`  | Save-preset sheet                                         |
| `settings.`    | Settings screen (language, accent, sound, account, about) |
| `onboarding.`  | Onboarding flow (4-slide first-visit intro)               |
| `privacy.`     | Privacy policy page                                       |
| `stepper.`     | Stepper sheet                                             |
| `lastSession.` | Last-session card                                         |
| `notFound.`    | 404 screen                                                |
| `timer.`       | Timer screen (count-up stopwatch controls)                |

### Platform-forked copy: the `.native` suffix

When a string differs between web and the native Android build, add a sibling key with a **`.native` suffix** (e.g. `onboarding.s3.body` → `onboarding.s3.body.native`) and pick between them at the call site with `isNativePlatform()`:

```tsx
<p>{t(isNativePlatform() ? 'onboarding.s3.body.native' : 'onboarding.s3.body')}</p>
```

Keep both variants in `strings.ts` with full `en`/`sv` parity. Native copy must not describe accounts, passkeys, or cloud storage (they don't exist on native), and privacy claims must stay consistent with `Privacy.tsx` and the 07h Play Data Safety declaration. Used by the 07g copy forks.

## Interpolation

Placeholders use `{paramName}` syntax:

```typescript
'run.phase.work': { en: 'Work · Set {idx} / {total}', sv: 'Arbete · Set {idx} / {total}' },
```

Pass params as the second argument to `t()`:

```typescript
t('run.phase.work', { idx: 2, total: 3 }); // → 'Work · Set 2 / 3'
```

Unknown placeholders are left intact (e.g. `{idx}` if `idx` is not in params). This is intentional — it surfaces missing params visibly rather than silently swallowing them.

## Language detection and persistence

`detectLanguage()` in `detect.ts` accepts an injectable `Pick<Navigator, 'language'>` (defaults to `navigator`). It maps any `sv-*` locale to `'sv'`; everything else becomes `'en'`.

Priority order on startup:

0. **Native override (Android):** on `isNativePlatform()`, language is forced to `'en'` unconditionally — both rules below are bypassed. The Android app is English-only because native voice recognises/parses English only (07f); a Swedish UI would just funnel users into a mic that can't understand them, and the Settings language toggle is hidden there. See [android-app.md](./android-app.md) Part 4.
1. `localStorage` key `takt.lang.v1` (values: `'en'` | `'sv'`).
2. `detectLanguage()` from `navigator.language`.

When the user changes language via `setLang()`, the new value is written to `takt.lang.v1` immediately. Authenticated users also sync their preference to D1 via the settings endpoint (Phase 5 PR 2+). Neither path is reachable on native — the toggle is hidden and the D1 sync is native-gated — so the forced `'en'` is the single effective language there.

## `useI18n()` hook

```typescript
const { lang, setLang, t } = useI18n();
```

| Property  | Type                   | Description                                 |
| --------- | ---------------------- | ------------------------------------------- |
| `lang`    | `Lang`                 | Active language code (`'en'` or `'sv'`)     |
| `setLang` | `(lang: Lang) => void` | Switch language and persist to localStorage |
| `t`       | `TFunc`                | Translate a key, optionally with params     |

`useI18n()` must be called inside `I18nProvider`. Calling it outside throws `'useI18n must be used inside I18nProvider'`.

## `TFunc` type

```typescript
type TFunc = (key: StringKey, params?: Record<string, string | number>) => string;
```

`StringKey` is derived from the keys of `strings`, so TypeScript autocompletes valid keys and errors on typos.

## Testing

Wrap any component that calls `useI18n()` with `I18nProvider` in tests:

```typescript
render(<MyComponent />, { wrapper: I18nProvider });
```

For tests that need to assert language-specific copy or switch languages, use `renderWithI18n` from `src/test-utils/render-with-i18n.tsx`:

```typescript
renderWithI18n(<MyComponent />, { lang: 'sv' });
```

For `detectLanguage`, stub `navigator.language` via `vi.stubGlobal` and restore with `vi.unstubAllGlobals()` in `afterEach`. Do not use `Object.defineProperty` — it mutates the shared jsdom environment with no automatic restore.
