# Store assets — Google Play listing

Reusable library for Takt's Play Store graphics. Some of these need refreshing every release (screenshots, when the UI changes); the generator makes that a one-command job.

## What's here

```
store-assets/
├── generate.mjs        # frames captures + builds feature graphic + copies the icon → upload/
├── captures/           # raw device screenshots (the source of truth for framing) — committed
└── upload/             # generated, ready-to-upload PNGs — regenerate with `pnpm store:assets`
```

Regenerate everything in `upload/`:

```bash
pnpm store:assets
```

## What maps to which Play Console field

Play Console → **Grow users → Store presence → Store listings** (graphics live under "Assets"):

| File (`upload/`)                  | Size      | Play field                       | Refresh cadence                        |
| --------------------------------- | --------- | -------------------------------- | -------------------------------------- |
| `app-icon-512.png`                | 512×512   | App icon                         | Rarely (brand change only)             |
| `feature-graphic-1024x500.png`    | 1024×500  | Feature graphic (required)       | Rarely                                 |
| `01-home.png` … `06-settings.png` | 1080×1920 | Phone screenshots (min 2, max 8) | **Every release where the UI changed** |

Play's screenshot rules the generator already satisfies: PNG, each side 320–3840 px, and a safe 9:16 frame (1080×1920) so a tall device capture is never rejected for aspect ratio.

## Refreshing screenshots for a new release

1. **Install the build you're shipping** on a connected Android phone (so the screenshots match what users get):
   ```bash
   pnpm cap:sync && cd android && ./gradlew installDebug && cd ..
   ```
2. **Tidy the status bar** (optional but nicer — clean clock, full battery, no clutter):
   ```bash
   adb shell settings put global sysui_demo_allowed 1
   adb shell am broadcast -a com.android.systemui.demo -e command enter
   adb shell am broadcast -a com.android.systemui.demo -e command clock -e hhmm 0900
   adb shell am broadcast -a com.android.systemui.demo -e command network -e wifi show -e level 4
   adb shell am broadcast -a com.android.systemui.demo -e command notifications -e visible false
   # …and when done: adb shell am broadcast -a com.android.systemui.demo -e command exit
   ```
3. **Capture each screen** you want, into `captures/` (navigate the app, then):
   ```bash
   adb exec-out screencap -p > store-assets/captures/home.png
   ```
   Keep the filenames the generator expects (`home`, `run`, `stopwatch`, `complete`, `presets`, `settings`), or edit the `SHOTS` list in `generate.mjs`.
   > Tip: the running-timer screen can occasionally capture as a black frame mid-transition — just re-capture.
4. **Regenerate and review:**
   ```bash
   pnpm store:assets
   ```

## Editing captions / the set

The screenshot set, its order, and the captions are the `SHOTS` array at the top of `generate.mjs`. Add/remove entries or reword captions there, then rerun.

## Notes

- **Fonts:** captions and the wordmark render in a system sans fallback, not Figtree (which isn't installed system-wide). Clean and legible, but not pixel-matched to the in-app wordmark. Good enough for the listing; swap in a rendered-Figtree path if you ever want exact.
- **`settings.png` currently shows the English/Svenska toggle.** The shipping native build hides that toggle (English-only, #138); the committed capture is from an older build. Kept deliberately — recapture from the current build if you'd rather it match, or just upload the other five screenshots.
- The app icon is copied from `public/icons/icon-512.png`, generated by `scripts/gen-icons.mjs` from the "takt" wordmark SVG — so it always matches the real launcher icon.
